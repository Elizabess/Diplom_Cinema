# Проектирование базы данных

Проект: Cinema Booking System.

Назначение системы: онлайн-бронирование билетов в кинотеатр и административное управление залами, фильмами, сеансами и ценами.

## 1. Общие решения

- СУБД: MySQL или MariaDB.
- Кодировка таблиц: `utf8mb4`.
- Движок таблиц: `InnoDB`.
- Первичный ключ таблиц: числовое поле `id`.
- Даты и время хранятся в формате `DATETIME`.
- Пароли пользователей хранятся только в виде хеша.
- Доступ к базе данных из PHP выполняется через PDO.
- Административная часть доступна только пользователю с ролью `admin`.

## 2. Пользовательские роли

В системе предусмотрены следующие роли:

- `admin` — администратор.
- `guest` — гость, неавторизованный посетитель сайта.

Гость может:

- просматривать список фильмов;
- просматривать расписание сеансов;
- выбирать места;
- бронировать билеты.

Администратор может:

- создавать и редактировать кинозалы;
- открывать и приостанавливать продажу билетов;
- создавать и редактировать фильмы;
- создавать и редактировать сеансы;
- настраивать цены;
- просматривать забронированные билеты.

## 3. Таблица users

Назначение: хранение учётных записей администраторов.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PRIMARY KEY, AUTO_INCREMENT | Идентификатор пользователя |
| `email` | VARCHAR(255) | NOT NULL, UNIQUE | Логин пользователя |
| `password_hash` | VARCHAR(255) | NOT NULL | Хеш пароля |
| `role` | VARCHAR(20) | NOT NULL, DEFAULT 'admin' | Роль пользователя |
| `name` | VARCHAR(255) | NULL | Имя пользователя |
| `created_at` | DATETIME | NOT NULL | Дата создания |
| `updated_at` | DATETIME | NULL | Дата изменения |

Правила:

- Пароль нельзя хранить в открытом виде.
- Для создания хеша используется функция PHP `password_hash()`.
- Для проверки пароля используется функция PHP `password_verify()`.
- Поле `email` должно быть уникальным.

## 4. Таблица halls

Назначение: хранение информации о кинозалах.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PRIMARY KEY, AUTO_INCREMENT | Идентификатор зала |
| `name` | VARCHAR(255) | NOT NULL | Название зала |
| `description` | TEXT | NULL | Описание зала |
| `rows_count` | INT UNSIGNED | NOT NULL | Количество рядов |
| `seats_per_row_count` | INT UNSIGNED | NOT NULL | Количество мест в ряду |
| `is_active` | TINYINT(1) | NOT NULL, DEFAULT 0 | Состояние продажи билетов |
| `created_at` | DATETIME | NOT NULL | Дата создания |
| `updated_at` | DATETIME | NULL | Дата изменения |

Правила:

- `is_active = 0` означает, что продажа билетов приостановлена.
- `is_active = 1` означает, что зал доступен для бронирования.
- Количество рядов должно быть больше нуля.
- Количество мест в ряду должно быть больше нуля.

## 5. Таблица seats

Назначение: хранение отдельных зрительских мест в кинозалах.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PRIMARY KEY, AUTO_INCREMENT | Идентификатор места |
| `hall_id` | BIGINT UNSIGNED | NOT NULL, FOREIGN KEY | Идентификатор зала |
| `row_num` | INT UNSIGNED | NOT NULL | Номер ряда |
| `seat_number` | INT UNSIGNED | NOT NULL | Номер места |
| `type` | VARCHAR(20) | NOT NULL, DEFAULT 'standard' | Тип места |
| `created_at` | DATETIME | NOT NULL | Дата создания |

Допустимые типы мест:

- `standard` — обычное место;
- `vip` — VIP-место.

Правила:

- Место принадлежит одному залу.
- В одном зале не может быть двух мест с одинаковыми номером ряда и номером места.
- Для одного места комбинация полей `hall_id`, `row_number`, `seat_number` должна быть уникальной.
- При удалении зала его места удаляются вместе с ним.

## 6. Таблица movies

Назначение: каталог фильмов.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PRIMARY KEY, AUTO_INCREMENT | Идентификатор фильма |
| `title` | VARCHAR(255) | NOT NULL | Название фильма |
| `description` | TEXT | NULL | Описание фильма |
| `duration_minutes` | INT UNSIGNED | NOT NULL | Продолжительность в минутах |
| `poster_url` | VARCHAR(255) | NULL | Путь к постеру |
| `is_active` |


TINYINT(1) | NOT NULL, DEFAULT 1 | Активность фильма |
| `created_at` | DATETIME | NOT NULL | Дата создания |
| `updated_at` | DATETIME | NULL | Дата изменения |

Правила:

- Фильм создаётся администратором.
- Неактивный фильм не показывается в пользовательском расписании.
- Продолжительность фильма должна быть больше нуля.
- Постер может храниться как локальный файл или ссылка.

## 7. Таблица screenings

Назначение: расписание сеансов фильмов.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PRIMARY KEY, AUTO_INCREMENT | Идентификатор сеанса |
| `hall_id` | BIGINT UNSIGNED | NOT NULL, FOREIGN KEY | Идентификатор зала |
| `movie_id` | BIGINT UNSIGNED | NOT NULL, FOREIGN KEY | Идентификатор фильма |
| `start_at` | DATETIME | NOT NULL | Дата и время начала |
| `end_at` | DATETIME | NOT NULL | Дата и время окончания |
| `price_standard` | DECIMAL(10,2) | NOT NULL | Цена обычного места |
| `price_vip` | DECIMAL(10,2) | NOT NULL | Цена VIP-места |
| `is_active` | TINYINT(1) | NOT NULL, DEFAULT 1 | Доступность сеанса |
| `created_at` | DATETIME | NOT NULL | Дата создания |
| `updated_at` | DATETIME | NULL | Дата изменения |

Правила:

- Сеанс связан с одним фильмом и одним залом.
- Один фильм может иметь много сеансов.
- Один зал может использоваться для многих сеансов.
- В одном зале не должно быть двух пересекающихся сеансов.
- Время окончания должно быть позже времени начала.
- Цена обычного и VIP-места не может быть отрицательной.
- Неактивный сеанс недоступен для бронирования.

## 8. Таблица tickets

Назначение: хранение забронированных билетов.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PRIMARY KEY, AUTO_INCREMENT | Идентификатор билета |
| `screening_id` | BIGINT UNSIGNED | NOT NULL, FOREIGN KEY | Идентификатор сеанса |
| `seat_id` | BIGINT UNSIGNED | NOT NULL, FOREIGN KEY | Идентификатор места |
| `user_id` | BIGINT UNSIGNED | NULL, FOREIGN KEY | Пользователь, если он авторизован |
| `booking_code` | VARCHAR(64) | NOT NULL, UNIQUE | Уникальный код бронирования |
| `qr_code_path` | VARCHAR(255) | NULL | Путь к QR-коду |
| `status` | VARCHAR(20) | NOT NULL, DEFAULT 'reserved' | Статус билета |
| `created_at` | DATETIME | NOT NULL | Дата бронирования |
| `updated_at` | DATETIME | NULL | Дата изменения |

Допустимые статусы билета:

- `reserved` — забронирован;
- `cancelled` — отменён.

Правила:

- Один билет относится к одному сеансу.
- Один билет относится к одному месту.
- Одно место нельзя забронировать дважды на один и тот же сеанс.
- Комбинация `screening_id` и `seat_id` должна быть уникальной.
- `booking_code` должен быть уникальным.
- QR-код должен содержать код бронирования, сеанс, ряд и место.
- Гость может забронировать билет без записи в таблице `users`.

## 9. Связи между таблицами

### users и tickets

Один пользователь может иметь много билетов.

```text
users 1 ──── много tickets
```

Связь необязательная, потому что гость может бронировать билет без авторизации.

### halls и seats

Один зал содержит много мест.

```text
halls 1 ──── много seats
```

### halls и screenings

В одном зале может проходить много сеансов.

```text
halls 1 ──── много screenings
```

### movies и screenings

Один фильм может показываться на многих сеансах.

```text
movies 1 ──── много screenings
```

### screenings и tickets

На один сеанс может быть забронировано много билетов.

```text
screenings 1 ──── много tickets
```

### seats и tickets

Одно место может использоваться в билетах на разные сеансы, но не может быть дважды забронировано на один и тот же сеанс.

```text
seats 1 ──── много tickets
```

## 10. Основные ограничения

- Email пользователя уникален.
- Код бронирования уникален.
- Комбинация `hall_id`, `row_number`, `seat_number` уникальна.
- Комбинация `screening_id`, `seat_id` уникальна.
- Нельзя создать сеанс с несуществующим залом.
- Нельзя создать сеанс с несуществующим фильмом.
- Нельзя создать билет с несуществующим сеансом.
- Нельзя создать билет с несуществующим местом.
- Нельзя забронировать место в неактивном зале.
-


Нельзя забронировать место на неактивном сеансе.
- Нельзя передать отрицательную цену.
- Нельзя указать нулевое количество рядов или мест.
